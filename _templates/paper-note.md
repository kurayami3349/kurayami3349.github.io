## 3. 方法
{: #method }

### 整体思路

说明输入、输出、模块职责和处理流程。按理解需要选择正文、表格或辅助图。辅助图应让读者直接看出一个关系，例如位移方向、接触状态变化、同尺度下的性能差异。多阶段方法可用表格说明各阶段的数据、目标与产物。

| 阶段 | 数据与输入 | 训练目标 / 处理过程 | 产物 |
| :--- | :--- | :--- | :--- |
| 阶段一 | 数据来源与输入 | 本阶段完成什么 | 输出供谁使用 |
| 阶段二 | 新增或复用的数据 | 与前一阶段如何衔接 | 最终输出 |

### 关键设计

解释关键模块如何工作，结合公式、具体例子和必要的图示展开。原图提供实验和实现证据；辅助图用位置、方向、长度、面积、轨迹或实物对照帮助理解。已由相邻表格或原图讲清的内容，合并呈现。

图中保留短标签、刻度和必要图例，解释与推导放在正文。自绘图优先使用可编辑的 SVG / HTML，图注简述依据、量纲和关键假设，alt 文本说明图意。阅读时先看到的应是几何或数值关系；只有文字框和连接线的内容，优先整理成段落或表格。

以清楚、可读为目标。marker、圈选或局部着色按需突出图要回答的问题，已有对比足够清楚时保持简洁。

图内公式单独检查排版与符号一致性。外链 SVG / PNG 中的 LaTeX 不会由页面 MathJax 自动渲染；复杂公式优先放在正文，确需入图时先用数学排版工具渲染再嵌入。预览时逐项核对上下标、希腊字母、矩阵、转置与逆号，以及字体缺字、重叠和裁切。

辅助图使用 `reading-figure` 紧凑版式，默认横向构图，在正文中以最多 600 px 宽、320 px 高呈现。按实际显示尺寸设计标签，并检查手机预览；信息过密时先精简内容。图注以一两句为宜。原论文图保留普通 `figure`，便于查看细节。

选配的辅助图写法：

```html
<figure class="reading-figure">
  <img src="/img/arxiv-论文编号/reading-comparison.svg" alt="说明可见的差异及其含义">
  <figcaption><strong>阅读重构 · 一个明确的问题。</strong> 数据或公式来源；理解该图所需的假设。</figcaption>
</figure>
```

图片放在 `img/arxiv-论文编号/`。替换以下路径与图注后，将 HTML 放入正文：

```html
<figure>
  <img src="/img/arxiv-论文编号/architecture.png" alt="描述图中内容">
  <figcaption><strong>原文 Fig. 1 · 图的主题。</strong> 解释图中机制或结果。来源：论文标题、版本与页码。</figcaption>
</figure>
```

长公式单独成段，条件概率使用 `\mid`：

```latex
$$
\pi(a \mid o, l) = \sum_z \pi(a \mid o, z)\,p(z \mid o, l)
$$
```

## 6. Insights · 思考与启示
{: #takeaways }

先给出对论文核心设计的判断，再展开已有阅读联想。选择最影响结论的一到两个问题深入分析，按论证需要组织小节：

- **主张与证据：** 论文希望证明什么？具体对比支持到哪一步？引用表格、条件和数值。
- **机制与替代解释：** 从公式、表示或对照设置推导可能的薄弱环节；判断收益是否也可由其他改变解释。
- **边界与检验：** 写清触发条件、预期失败方式，以及能区分两种解释的最小对照。缺失消融对应归因待定；数学反例、已观察失败与机制假设分别标清。
- **跨论文联系：** 保留原有思考，用站内链接连接基础知识和可比较的方法，说明比较的是哪一层设计。

围绕具体技术判断写作，保留必要假设与反例。泛泛的“样本少、还需更多实验”应落实成会改变哪条结论、如何检验。每篇的分析深度由证据决定。
